# Learnings

Surprises, gotchas and fixes found while building. One entry per line. Newest last.

Format: `- [area] What happened. Why. Fix or workaround. (source: task file / doc link)`

- [livekit/rpc] RPC codes 1001-1999 are reserved for LiveKit. App codes moved to 2001-2007. (RPC doc "Errors"; ADR-020)
- [livekit/attributes] A participant with `canUpdateOwnMetadata` can rewrite its own attributes, including `role`. Human tokens must not get it. (participant-attributes doc; ADR-022)
- [livekit/attributes] Attributes are capped at 64 KiB total across keys and values. (participant-attributes doc)
- [livekit/agents] `set_participant` takes one identity. The agent hears one human at a time. (`room_io.py`)
- [livekit/agents] `ToolHandlingOptions(tool_reply_after_audio=...)` from early research does not exist in livekit/agents. Use `StopResponse` or `cancel_tool_reply()` to control replies. (code search; events doc)
- [livekit/agents] livekit-agents 1.8.7+ reports realtime `e2e_latency` in assistant message metrics when local VAD is set. (changelog 1.8.7)
- [tooling] The docs MCP may be pending approval in a session. `lk docs search|get-page|code-search|changelog` gives the same source from the shell.
- [livekit/realtime] GPT Realtime 2.1 is turn-based and owns turn detection (semantic VAD by default). Starter STT/TTS, TurnDetector, adaptive interruption, and preemptive_generation conflict; drop them and keep noise cancellation. (docs: /agents/models/realtime/openai, /agents/logic/turns#realtime-models; task 01)
- [livekit/cli] `lk agent init AGENT-NAME` uses that name as both the directory and the dispatch name. Override `@server.rtc_session(agent_name=...)` from `AGENT_NAME`. (CLI agent-development doc; task 01)
- [livekit/cli] CLI 2.19+ `lk agent dev` registers under a random `dev-` deployment, so a starter token that dispatches production may miss the local worker. Pass `--deployment production` when no cloud agent exists. (CLI agent-development doc; task 01)
- [agent/tests] The Python starter's pytest file is fully commented, so `uv run pytest` exits 5 with 0 tests. Add a tiny import/instructions smoke test. (task 01)
- [livekit/agents] First GPT Realtime job stalled ~900ms importing `openai.types.realtime` on the job process. Prewarm that module if cold-start lag matters. (task 01)
- [livekit/logs] Worker INFO logs the job and RoomIO link, not the assistant transcript. The reply is in the web chat UI. (task 01)
- [web] The embedded preview browser has no mic: `getUserMedia` throws `NotSupportedError`. The /player page must catch mic failure and show a message. Voice tests need a real browser. (audit 01)
- [livekit/agents] Adding plain `vad=` to a realtime session keeps server turn detection; adding `turn_detection` or `interruption` with it switches to client-side turns. VAD is needed for `e2e_latency`. (agent_activity.py; audit 01)
- [agent/tests] Importing agent.py raises if AGENT_NAME is unset, so a fresh clone fails pytest. Set a default in tests/conftest.py and keep the fail-fast raise. (audit 01; task 01 r2)
- [facts] Basketball-Reference series page now includes the Game 7 score, series winner and Finals MVP. Shipped claims use Games 1-6 box scores, the game list, and the 2015-16 team page only. (source: task 02)
- [facts] Game 5 series summary says "PTS 2 tied 41"; the names are only on the box score (LeBron James 41, Kyrie Irving 41). (source: task 02)
- [facts] Game 5 Warriors box lists Draymond Green as "Player Suspended". Game 3 box lists Kevin Love as Inactive. (source: task 02)
- [deck] Architecture sketch caption "Two defenders jump the ball" fails callout rule 5 (spelled-out number). Use "Both defenders jump the ball". (source: task 02)
- [facts] Page titles contain a pipe before "Basketball-Reference.com". Drop the site suffix in the Verified cell so the markdown table still has five columns. (source: task 02)
- [tooling] This worktree has `python3` and `uv`, not `python`. Deck commands in AGENTS.md use `python3`. (source: task 02)
- [deck] Two plays on s4 need different formations. `play.start` (ADR-023) lets the short-roll begin as a pick-and-roll instead of the stagger. (source: task 02 round 2)
- [deck] A stagger screener cannot hold the ball. Put Klay at the top as the passer; Curry only gets it on a pass. (source: task 02 round 2)
- [deck] Trap geometry: both trappers finish beside the handler toward the rim, not above him toward half court. (source: task 02 round 2)
- [deck] Slide 5 pace is F19 (Warriors). Say "our pace", not theirs. Love copy can only use F13 + F17. (source: task 02 round 2)
- [facts] A soft claim ("Love produced when he played") passed planner review but was false across Games 5-6. Any slide sentence that judges performance needs a fact per game it covers, not one game. (audit 02)
- [facts] Basketball-Reference returns 403 to curl and plain WebFetch. A search-provider fetch (parallel-search web_fetch) reads the full pages. (audit 02)
- [facts] `split("|")` plus `cols[:5]` dropped a verified row when a cell had a pipe, with no error. Require exactly five columns. (source: task 02 round 3)
- [facts] `startswith("y")` skipped `Y` silently. Match `y\b` / `n\b` case-insensitive and exit if the cell is neither. (source: task 02 round 3)
- [deck] Short-roll corner arrows are reads, not passes made. Mark `"option": true` and ignore option arrows in the ball rule. (source: task 02 round 3)
- [deck] Trap tests must key on `"action": "trap"`, not the caption, or a wording change disables the radius check. (source: task 02 round 3)
- [web/token] `TokenSource.endpoint` POSTs a `TokenSourceRequest` proto body, not `{"role":"player"}`. Use `TokenSource.custom` for the role-checked route. (source: task 05; livekit-client TokenSource.ts)
- [livekit/attributes] `localParticipant.setAttributes({role:'coach'})` without `canUpdateOwnMetadata` fails with `SignalRequestError` code 15 "does not have permission to update own metadata". Role stays `player`. (source: task 05)
- [livekit/cli] `lk room participants get --room NAME -i ID` prints `attributes.role`. Human tokens omit `canUpdateMetadata`; the agent has it. (source: task 05)
- [web/token] `canPublishSources` is a `TrackSource[]` on mint and strings in the JWT (`microphone`). Assert the decoded string, not the enum number. (source: task 05 r2; livekit-server-sdk grants.ts)
- [web/token] `RoomConfiguration` JWT includes protobuf defaults (`name`, `restartPolicy`, empty `tags`). Assert named fields, not `toEqual` on the whole config. (source: task 05 r2)
- [web/token] Coach room format `^fr-[0-9a-f]{16}$` is checked in `parseTokenRequest`, so invalid ids 400 before `listRooms`. (source: task 05 r2)
- [livekit/inference] Free plan: 5 concurrent Inference sessions and $2.50 credit (about 50 realtime minutes). A parallel eval run hit 429 and a usage alert. Run evals at concurrency 1 and stop stale runs. (lk docs pricing-info)
- [livekit/rpc] Nested RPC works: the player can `performRpc` `debug_probe` on the agent while registered as the `show_slide` handler; the agent then `perform_rpc`s back to that same player. (source: task 03 live probe)
- [web/rpc] Two `requestAnimationFrame`s is a working "after paint" ack. Applied `show_slide` round trips were min 103.5 / median 117.2 / max 121.7 ms (n=10). (source: task 03)
- [agent/debug] Skipping `AgentSession` under `CHALK_DEBUG=1` keeps inference off, but the starter `useAgentErrors` then treats the agent as failed and the session UI ends the call after ~20s. Finish the RPC probe before that, or keep a dummy session. (source: task 03)
- [livekit/js] Browser `performRpc` clamps `responseTimeout` to at least 8000ms on the caller. That does not change the agent's Python `perform_rpc(..., response_timeout=3.0)`. (livekit-client RpcManager; task 03)
- [spike 3] RESULT PASS. `show_slide` RPC round trip with ack after two rAFs: min 103.5 ms, median 117.2 ms, max 121.7 ms (n=10, local agent to LiveKit Cloud). Stale seq, 2001, 2004, 2007 and missing player (1401) behave per contract. Late-joining coach renders from attributes. (task 03)
- [livekit/rpc] livekit-client sends the transport ACK before the handler runs. A frozen tab sends none, so the caller fails on `max_round_trip_latency` (default 7 s, code 1501), not on `response_timeout` (1502). A hidden tab pauses rAF, so an after-paint ack must not wait on rAF when `visibilityState` is hidden. (audit 03)
- [agent/seq] A restarted or redispatched agent starts seq at 0 while the open tab keeps its last seq, so every command reads as stale. The browser resets its seq when the agent identity changes. (audit 03)
- [livekit/inference] LiveKit Inference returned 429 on a single realtime session with nothing else running, after the earlier eval runs. Likely the free credit is spent (not confirmed; dashboard shows it). OpenAI is primary per ADR-024. (task 08)
- [livekit/agents] `RealtimeModelFallbackAdapter`: recoverable errors are left to the plugin's own reconnect; only non-recoverable errors swap models; if every model fails the adapter escalates and the AgentSession closes. The /player page must show a clear message when the session ends on error. (realtime_fallback_adapter.py)
- [livekit/realtime] `RealtimeModelFallbackAdapter` requires matching `audio_output`, `turn_detection`, and `supports_overlapping_speech`. OpenAI plugin and Inference defaults already agree; no extra turn-detection config. (adapter source; task 08)
- [livekit/realtime] Adapter `.model` is `RealtimeModelFallbackAdapter`; the availability event payload is `realtime_model` plus `available`. OpenAI plugin reports `provider=api.openai.com`. (`realtime_fallback_adapter.py`; task 08)
- [dotenv] `OPENAI_API_KEY=sk-invalid` on `make agent-dev` wins over `.env` / `.env.local` because `load_dotenv` does not override. Confirmed by OpenAI `invalid_api_key`. (task 08)
- [livekit/inference] After OpenAI invalid-key failover, Inference WS returned 429 (5-session / credit cap). Adapter `_active` was `inference.realtime.openai`; no spoken reply. Do not retry extra turns. (task 08)
- [livekit/rpc] `perform_rpc(..., max_round_trip_latency=2.0)` (SDK default 7s) bounds a frozen-tab 1501 wait. Tradeoff: rare LiveKit Cloud relay retries that need more than 2s may fail instead of succeeding. (source: task 03 r2; participant.py)
- [web/fonts] Archivo loaded with static weights plus `font-variation-settings: 'wdth' 78` collapsed UI glyphs (lower-third and status text vanished). Drop the width axis unless Archivo is loaded as a variable font. (source: task 07)
- [web/css] A three-column grid still placed the court in the empty `auto` cutout column when a slide had no side cutouts, shrinking slide 6. Use a two-column template when that slot is unused. (source: task 07)
- [web/prettier] `prettier --write` reformats `web/lib/deck/deck.json` and would drift the synced copy. Ignore `lib/deck/*.json`. (source: task 07)
- [web/court] Deck y=0 is the baseline. Mapping SVG as y-down puts the rim at the top; rotate to `toSvg(x,y)=(100-y,x)` so the basket sits on the right like the concepts. (source: task 07)
- [web/court] A 55% square court at 1920×1080 is taller than the sheet once the status strip is reserved. Size the court frame by height (`aspect-ratio: 1; height: 100%; flex: none`) so the strip stays on screen. (source: task 07 r2)
- [web/cutout] The paper-border drop-shadow covered Courier captions. Rotate only the photo and sit the label below the shadow with z-index. (source: task 07 r2)
- [web/status] Wide Archivo tracking turns "turn" into "tum" (rn). Use letter-spacing 0 and disable liga/calt on the strip. (source: task 07 r2)
- [deck] The first `fact_id` is not always the slide's featured card. Optional `featured_fact_id` (must be on that slide) picks it; omit the field for no card. (source: task 07 r2)
- [spike 1] RESULT PASS. Mid-session `session.room_io.set_participant(coach)` with gpt-realtime-2.1 (OpenAI plugin): 0.66 ms, full switch to clicker 46 ms, no session reset, player audio ignored, 4 coach turns -> 4 acked `show_slide`. Tested without a mic using OpenAI TTS clips published by `lk room join --attribute role=coach --publish clip.ogg`. (task 06)
- [livekit/agents] By default the session closes when the linked participant disconnects. After switching to the coach, a coach hangup ends the whole session. See ADR-025. (task 06)
- [spike 1] RESULT PASS. `session.room_io.set_participant(coach)` mid-session with GPT Realtime 2.1 (OpenAI plugin) switches the ear without resetting the realtime session. `set_participant` 0.66 ms; full switch including `update_instructions` + `mode=clicker` 46.23 ms. (task 06)
- [livekit/agents] Default `RoomOptions.close_on_disconnect=True` closes the AgentSession when the linked coach leaves (`CLIENT_INITIATED` → `CloseReason.PARTICIPANT_DISCONNECTED`). It does not fall back to the player. Proposed rule (not built): `close_on_disconnect=False` and `set_participant(player)` on coach leave. (room_io.py; task 06)
- [livekit/cli] `lk room join --publish file.ogg` stays in the room after the file unless `--exit-after-publish`. Using `--exit-after-publish` on the linked coach would close the session after the first clip. (lk 2.19.0; task 06)
- [livekit/examples] `examples/voice_agents/toggle_io.py` is gone from livekit/agents main (docs MCP returned only the examples README). The API is still `RoomIO.set_participant` in `room_io.py`. (task 06)
- [livekit/realtime] OpenAI TTS "Assistant, show the Kyrie slide." transcribed as "Distant, show the Kyrie slide." The model still called `show_slide(s3_kyrie)`. (task 06)
- [tooling] Killing the `pnpm dev` parent can leave a reparented `next dev` child. Stop that PID too. Never `pkill`. (task 06)
- [spike 2] RESULT: correct tool 96-100%; any speech before tool 57% (config B); slide content before tool 0 of 344 (planner review). Pre-tool speech is a short announcement of the topic. Kept Realtime (ADR-026). (task 04)
- [spike 2] A title-only tool result made the model invent slide content. Tool results must carry the slide's points, notes and facts. (task 04)
- [spike 2] Two tool calls in one response ran in order with no overlap (second start 760-980 ms after first end). (task 04)
- [player/debug] The `CHALK_DEBUG=1` agent registers `debug_probe` but does not start an `AgentSession`; the starter `session.start()` waits for an agent state that this probe worker never publishes, leaving `/player` on its opening screen. Use the realtime worker to verify rendered live-player behavior; the probe alone can verify RPC handlers. (task 10)
- [player/reconnect] Reloading `/player` requests a new player token and the token route creates a new random room, so a hard reload cannot restore the previous room's slide attributes. State seeding is applicable to reconnects or late joiners that reuse the same room. (task 10; ADR-008)
